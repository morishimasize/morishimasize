# ✏️ ひっさんノート

iPhone・iPadで使う、子ども向けの筆算電卓です。たし算・ひき算・かけ算・わり算を、筆算と手順で確認できます。

## 起動と使い方

[ひっさんノートを開く](https://morishimasize.github.io/morishimasize/)

iPhone・iPadでSafariのアドレスバーを出さずに使うには、Safariで上のページを開き、共有メニューから「ホーム画面に追加」を選びます。「ウェブアプリとして開く」が表示されたらオンにして追加し、ホーム画面のアイコンから起動します。

最初の画面で、大きな3つのボタンから使い方を選びます。

1. **こたえを みる**：2つの数と演算を入力し「ひっさんを みる →」を押します。「つぎへ」「まえへ」で解き方を確認でき、「ぜんぶ みる」で答えをすぐ表示できます。
2. **じぶんで とく**：2つの数と演算を入力し「ノートに かく →」を押します。問題の式が印字されたノートに途中計算と答えを書き、ミニノートで読み取りを確認して「まるつけ」を押します。
3. **けいさんゲーム**：問題を選んで手書きで解きます。3問で絵の1/4、12問で1枚完成します。正解時の記録と途中ノートは自動保存し、次回は「つづきから あそぶ」で再開できます。

各画面の左上の「← はじめに」で、3つの入口へ戻れます。ゲームの保存先は同じ端末・同じブラウザ内です。端末間の同期はありません。電卓の手書き途中経過は保存対象に含みません。

数字は「ひとつめの かず」「ふたつめの かず」を選んで入力します。「ひとつ けす」は選択中の数の末尾を1文字削除し、「ぜんぶ けす」は両方の数を消します。横向きで高さが短い画面では、式と演算を左、数字ボタンを右に表示します。各数は最大5桁の非負整数です。わり算は整数の商とあまりを表示します。0によるわり算と、答えが負になるひき算には案内を表示します。

ローカルで起動するときも `index.html` が入口です。`calculator.html`・`home.css`・`home.js`・`steps.js`・`pop-theme.css`・`icon.png` と `assets/`・`prototypes/` を含むフォルダ構成を保って配置してください。電卓は `calculator.html`、ゲームと手書きノートは `prototypes/full-notebook.html` の共通処理を使用します。旧 `index.html?mode=…` の電卓URLは、式を引き継いで `calculator.html` へ移動します。

## 手書きノートの操作（正式採用）

「じぶんで とく」と「けいさんゲーム」は同じ手書きノートを使います。新しい問題の式は右寄せで印字されます。前の版から再開したゲームの途中ノートは、保存した位置で開きます。Apple Pencilは不要です。

- **1本指**で数字を書く。**2本指**を広げる・縮めるとノート全体を拡大・縮小し、2本指を動かすと表示位置を移動します。
- 方眼の上下に同じ道具が並びます。**ぜんぶ かきなおす**と**まるつけ**は、下の道具と一緒に画面内に収まります。横向きは右下に、縦向きは方眼の下にミニノートがあります。
- **ぜんたい**で拡大前の表示に戻ります。上の式も方眼の一部なので、方眼と一緒に拡大・移動します。画面が狭くスクロールが必要なときは、左右のグレーの帯からページを動かせます。
- **せん**を選び、段の下を押すと横線が入ります。**けしゴム**で数字と追加した横線を消し、**もどす**で復元できます。**ヒント**では書く場所が表示されます。
- 2本目の指が触れたら書きかけを取り消し、拡大・移動へ切り替えます。完了済みの文字や線はそのままです。
- 新しい問題・保存からの再開は全体表示で始めます。同じ問題のツール切替や読み取りから戻る際は拡大位置を保ちます。ゲームの筆跡・横線・採点・絵の記録は従来の保存を引き継ぎます。

筆算に使う桁数と段数に合わせて方眼のマス数を変え、画面内に収まる大きさで表示します。短い問題は少ないマスで大きく書けます。長い問題では、見やすい場所を2本指で拡大できます。

ペンや指を離すと、ミニノートに読み取り結果が出ます。読み取りにくい数字は、手書きのマスとミニノートの両方に黄色い「？」が出ます。ミニノートを押すと広げて数字・小さい数字・線を直せます。同じマスの筆跡を書き直すと、そのマスを読み直します。「まるつけ」を押すと、正解なら筆算ノートに大きな赤丸が出ます。見直す数字は赤い枠と×、書き忘れたマスや線は赤い点線で示します。

指摘されたマスは、消しゴムで空欄にしても目印が残ります。正しい数字が読み取れたマスから赤い目印が消えるので、一つずつ直せます。直し終えたら、もう一度「まるつけ」を押します。

式の上や印字された数字のそばに書いた補助数字は、メモとして扱います。繰り上がり・繰り下がりのメモは、数字の違いや読み取りの「？」があっても採点に影響しません。わり算の商は式の上に書き、途中式や答えと一緒に採点します。

0〜9の読み取りは端末内で行い、数字ごとに、傾きや線のつながり方が異なる手書きの見本と照らし合わせます。

見本と検証データの一部には、E. Alpaydin と F. Alimoglu が公開した筆跡の座標を、縮尺と座標の向きをそろえ、点を間引いて使用しています。見本と異なる書き手による3,498件を1マスに収めて読み取る比較では、0〜9すべてで正しく確定できた件数が増え、全体では53.7%から78.3%に上がりました。 [UCI Pen-Based Recognition of Handwritten Digits](https://doi.org/10.24432/C5MG6K) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

### 読み取り改善への協力

読み取り改善用の自動送信は最初からオンです。手書きノートはそのまま使えます。送信を止めたり再開したりするときは、開始画面の「おとなの せってい」を開きます。

手書きノートの確認画面で1桁を直して閉じると、その数字の筆跡だけを切り出し、修正前後の数字と読み取りのバージョンを自動で送ります。筆跡は位置と縮尺をそろえた座標です。通信できないときは端末に一時保留し、通信が戻ったときやアプリを開いたときに再送します。「じどうそうしんを とめる」で未送信分を消し、その端末からの送信を止められます。

収集データは管理者だけが受け取りページからJSONで取得できます。 [ひっさんノートの筆跡受け取り](https://hissan-note-feedback.artfulcookie1.chatgpt.site/)

集まった修正データで、読み取り候補の点数が近いときの判定ルールを自動で見直します。同じ種類の筆跡について学習用8件以上・検証用4件以上が集まると評価し、別の筆跡で改善し、公開データと既存の読み取り例を使った回帰確認も通ったルールを配信します。配信内容は判定ルールと版番号です。後から検証を通らなくなったルールは配信から外れます。

配信された更新は、アプリが取得した後に次のノート画面を開いたときに使います。管理ページでは修正データの件数と配信中のルール数を確認できます。

1段だけを別画面で拡大するボタンは通常画面から外しました。以前の試作URL（`touch=1`）も同じ操作で開けます。下の過去の試作記録より、この操作説明が現在の仕様です。

## ノート風のデザイン

- 両画面をA案「ぷっくりシール」に統一。ピンクの背景、水色のチェック、黄色のノート枠を使用。リングなしの普通のノート風に統一。
- 方眼紙と光沢のあるボタンをCSSで描画。数字と説明の面は白を保ち、鉛筆シールは外縁に配置。
- 入力画面は大きな数の選択欄と、5列の数字ボタン。
- 解答画面は「式 → 筆算と手順 → 答え」の順に表示。
- 横幅760px以上では筆算と手順を左右に配置。それ以外は上下に配置。
- 解答の筆算は表示領域に合わせて縮めます。大きな式で文字を読みやすく保つ必要があるときは、筆算欄の中を動かせます。
- 現在書く数字と見る数字を強調し、位の名前をひらがなで表示。

モックアップ画像を画面全体に貼る方式ではありません。ボタン・数字・手順はHTMLで生成するため、計算内容に合わせて変わります。背景の構図や端末のフォントにより、見本画像とは多少見た目が異なります。

## 主な処理

`calc()` が入力を検証し、`rAdd()`・`rSub()`・`rMul()`・`rDiv()`を呼び出します。`steps.js` の `buildLesson()` が、その計算の全手順と盤面のスナップショットを生成します。`showLesson()` で画面を組み立て、`renderLesson()` で現在の手順だけを表示します。`previousLesson()`・`nextLesson()`・`toggleLessonOverview()` が操作を処理し、`backToInput()` で入力画面へ戻ります。

桁幅は `steps.js` のモデルの `columns`（通常58px）、間隔は12px、行の間隔は70pxです。盤面の基本配置は `calculator.html` のCSS末尾「1手順ずつ進める解答画面」、採用デザインの色・装飾は `pop-theme.css` から調整できます。

### 四則演算の手順送りを本体に実装

- 固定の例だけの試作から、入力した最大5桁の数で動く処理に変更しました。
- 「まえへ」「つぎへ」を画面下に固定し、最後の手順では「もういちど」に切り替えます。
- 上部の式の答えは途中で「？」、最後または「ぜんぶ みる」で表示します。
- 「ぜんぶ みる」は完成した盤面を表示し、「ひとつずつ みる」で直前の手順に戻ります。
- 今書いた数字はオレンジ、計算で見る数字は黄色の背景で示し、説明も1手順ずつ切り替わります。
- 割り算は「たてる・かける・ひく・おろす」を分けます。途中の商の0、あまり、割られる数が小さい場合も扱います。
- ひき算は、連続する0をまたいで10を渡す過程を順番に表示します。
- かけ算は各桁の計算とくり上がりを表示し、複数段の結果をたす過程も桁ごとに表示します。
- 長い筆算は盤面の中でスクロールし、手順で見る場所へ表示位置を合わせます。入力画面から戻った場合も数値は残ります。

検証：四則演算709件で、完成した盤面の答え・割り算のあまり・全手順の桁位置・くり下がりの連鎖・商の途中の0を確認。戻る、進む、完成形から元の手順への復帰、最後からの再スタート、入力範囲の検証も確認しました。試作ページは別途残しています。

## 手書き解答と絵が完成する試作（2026-11-21）

[手書きの3問とできたえほん](https://morishimasize.github.io/morishimasize/prototypes/game-preview.html) に更新しました。本体の `index.html` と計算手順は変更していません。以前のシール試作の保存データも削除していません。

- 足し算・引き算・掛け算・割り算×3段階、各4問から3問を出題。
- 解答はノートのマスにペン・指・マウスで直接書きます。1マス1桁、答え4マス、必要な場合は余り2マス。数字は左から続けて書き、余ったマスは空欄にできます。
- Pointer Eventsで筆跡を保持し、画面の回転・戻る進む・絵本との行き来でも描き直します。途中の問題と筆跡は再読み込みでリセットします。
- 「かいたすうじをよみとる」で認識結果を表示し、「このすうじでさいてん」を押すまで判定しません。認識結果は数字入力で修正でき、書き直しにも戻れます。判定後も「よみとりをなおす」で確認に戻れます。
